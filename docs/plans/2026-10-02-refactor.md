# Refactor & Restructure Plan

**Goal:** Make the codebase tidy and easy to maintain: content separated from layout, duplicated UI extracted, one source of truth for site config, and a clear folder structure.

**Principle:** Phase A changes **zero** pixels. Anything that changes what visitors see goes to Phase B, where each item is a separate decision.

**Branch:** `refactor/structure` (off `main`). Atomic commits, ≤400 lines each. Do not commit the untracked favicon files or the `.pnp.*` files.

### Header variants (do not flatten these)
- Tour: `text-[5rem]` on mobile, `shrink-0`, and smaller mobile h2 (`text-2xl tracking-wide md:text-6xl md:tracking-widest leading-tight`). These exist because "Persembahan" is long.
- Music, Gallery, Contact: the header wrapper is its own `container mb-16`. About, Tour, News: the header sits inside a `container relative z-10` with a `mb-16` div.

→ `SectionHeader` takes `number`, `eyebrow`, `title`, `accent`, and a `compact` prop for Tour.

### Dead or misleading code
- `app/page.tsx` is `"use client"` for the whole page; only Plasma needs it.
- `Hero.containerRef` is unused. In Plasma, the `mousePos` ref is redundant and `useCustomColor` is always 1.
- `globals.css`: `section { background }` is dead because every section sets a `bg-*` class. **But** `section#home { transparent }` beats the Hero's `bg-black/80` through ID specificity, so the Hero is transparent right now. Remove both rules together **and** change the Hero to `bg-transparent`, then verify with computed styles.
- `tailwind.config.ts`: `./pages/**` path doesn't exist. `chart-*` and `popover` tokens are unused. `fade-in`, `slide-up` and `slide-down` animations need a grep before removal.
- `globals.css`: the light-mode `:root` values are never used (`<html class="dark">` is hard-coded).
- Commented-out news items in News.tsx.
- `build-output.log` is tracked in git.
- `package.json`: name is `rock-band-portal`, and `export` duplicates `build`.

## Target structure

```
app/
  layout.tsx            # metadata + JSON-LD read from content/site.ts
  page.tsx              # server component
  robots.ts, sitemap.ts # use SITE.url + NAV_SECTIONS
  globals.css
components/
  layout/      Navigation.tsx, Footer.tsx
  sections/    Hero, About, Music, Tour, Gallery, News, Contact
  ui/          SectionHeader, CornerBrackets, LabelDivider, MagneticButton
  background/  Plasma.tsx, PlasmaBackground.tsx (client wrapper, dynamic ssr:false)
content/                # ← band edits ONLY this folder to update the site
  site.ts      # name, url, tagline, description, email, linktree, location, socials, nav sections
  about.ts     # story paragraphs, stats, members
  music.ts     # featured release (artwork, spotify embed, MV id), platforms
  shows.ts     # tour dates
  gallery.ts   # photos
  news.ts      # news items (incl. external link per item)
lib/
  utils.ts     # cn(), asset(path), scrollToId(id)
```

`asset(path)` keeps today's behaviour exactly: `` `${process.env.NEXT_PUBLIC_BASE_PATH || ''}${path}` ``.

## Other things found (outside refactor scope, flagging only)

1. **🔴 Contact form is probably broken in production.** `deploy.yml` does not pass `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY` to the build step, so the build falls back to `"YOUR_ACCESS_KEY_HERE"`. Fix: add `NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY: ${{ secrets.NEXT_PUBLIC_WEB3FORMS_ACCESS_KEY }}` to the build `env`. Separate commit, should be done first.
2. **Hosting is inconsistent.** CI deploys to GitHub Pages `/estrid.web`, but `metadataBase`, robots and sitemap use `https://estrid.my`. Icon paths (`/favicon.ico`) have no basePath, so they 404 on GH Pages. `@vercel/analytics` only works on Vercel. **Where does the site actually live?**
3. Untracked `public/images/apple-touch-icon-180x180.png` and `favicon-192x192.png` aren't referenced anywhere; the correctly sized files are already in `public/`. Probably leftovers to delete.
4. `yarn lint` is broken (needs `eslint.config.mjs` + `@eslint/eslintrc` for PnP). Optional chore.
